# AGENTS.md — openfortivpn-gui

Living spec for humans and AI agents. Update this file on any structural or behavioral change.
Repo: `git@github.com:marcosjoao37/openfortivpn-gui-rs.git` (branches: `main` stable, `development` work). Maintainer: João Marcos Silva e Araújo <marcosjoao377@gmail.com>. License: GPL-3.0-or-later.
Target machine reference: CachyOS (arch-like), KDE Plasma on Wayland, user `joao`. Linux-only project (depends on the `openfortivpn` binary); no Windows/macOS support planned.

---

## 1. Purpose

Desktop GUI wrapping the `openfortivpn` CLI so the user never opens a terminal.
Reference command (seed of the default profile):

```
sudo openfortivpn vpn2.cetiqt.senai.br:10443 -u joao.araujo --trusted-cert 10adad89836d4dbb03570776d469473ddb5dd25ceb6b60826f174275d8c1cfd3
```

## 2. Tech stack (decided)

| Concern | Choice | Rationale |
|---|---|---|
| Language | Rust, stable, edition 2021 | user requirement |
| UI | **egui / eframe 0.29** (immediate mode) | pure-Rust build inside Docker, no Qt/C++ toolchain. Decided over `cxx-qt`/`qmetaobject-rs` (build complexity) |
| Tray | **tray-icon 0.19** with `default-features = false` (drops the `libxdo` runtime dep) + muda menus, libayatana-appindicator backend | StatusNotifierItem/DBusMenu → renders on Plasma, XFCE, GNOME w/ AppIndicator extension. GTK main loop is pumped non-blockingly from the egui update loop |
| Serialization | serde + serde_json | profiles in JSON (user requirement) |
| Single instance | unix socket in `$XDG_RUNTIME_DIR` | second launch sends "show" and exits |
| Window close | Session loop: close destroys the eframe window; headless tray loop keeps the process and recreates windows on demand; backend forced to X11 (XWayland) when `DISPLAY` exists | winit 0.30 Wayland backend cannot hide/restore/focus/unminimize (all no-ops) and hides leave zombie surfaces; on X11 the loop exit closes the X connection, killing the window for real. Without any X11 display: Wayland backend + minimize fallback. Tray menu stays live both in-window and headless (verified: KWin client count 0 after close, window recreated on relay) |
| Process mgmt | std::process + setsid/pgid | group kill of `sudo openfortivpn` |
| Sudo password | remembered for the session in RAM (`Zeroizing`), cleared on exit or auth failure | user decision |
| Crypto on secrets | none stored; zeroize for in-memory passwords | passwords never persisted |

Runtime system deps (checked/warned by installer): `gtk3`, `libayatana-appindicator`, `libxkbcommon-x11` (winit X11); works under Wayland via XWayland or native Wayland backend. Close-to-tray is implemented by intercepting `close_requested` in `update()` + `ViewportCommand::CancelClose`/`Visible(false)` (eframe 0.29 has no `App::on_close_event`).

## 4. Data: profiles.json (0600)

Path: `$XDG_CONFIG_HOME/openfortivpn-gui/profiles.json`

```json
{
  "version": 1,
  "selected": "<profile-id>",
  "profiles": [
    {
      "id": "uuid4",
      "name": "CETIQT",
      "server": "vpn2.cetiqt.senai.br:10443",
      "username": "joao.araujo",
      "trust_cert": true,
      "trusted_cert": "10adad89836d4dbb03570776d469473ddb5dd25ceb6b60826f174275d8c1cfd3",
      "interface": null
    }
  ]
}
```

- VPN password and sudo password are **never** persisted (VPN password typed on every connect; sudo policy per Q2).
- `interface` (optional override, e.g. `ppp0`); null = autodetect first `ppp*|tun*` appearing after connect.
- First run with no file: seed profile "CETIQT" from §1 reference command.

## 5. Command execution (secrets never on argv)

1. Write temp config `%TMP%/ofg-<uuid>.conf` (0600): `host = <host>`, `port = <port>`, `username = ...`, `password = ...`, `trusted-cert = <sha256>` (if enabled).
2. Sudoers probe (cached, re-probed on auth failure):
   - `sudo -n -l` succeeds + lists `/usr/bin/openfortivpn` with `NOPASSWD:` → run `openfortivpn --config <file>` via `sudo -n`.
   - Otherwise → GUI asks sudo password (Q2 policy), run `sudo -S -p '' openfortivpn --config <file>`, password on stdin. Wrong password → surfaced error, retry.
   - openfortivpn not installed → never reach this; banner state instead (§6).
3. Spawn with `pre_exec` setsid → own process group; terminate = SIGTERM to pgid, then SIGKILL after 5 s (covers sudo + openfortivpn + pppd).
4. stdout/stderr → log ring buffer (last ~500 lines, shown in collapsible "Connection log").
5. Delete temp config on exit (drop guard).
6. Unknown-cert capture: parse stderr for `SHA256 fingerprint: ([0-9a-f]+)` → per Q3, offer "Trust this cert" button filling the profile field (requires disconnect + reconnect to apply).


- Red banner state: openfortivpn missing → ALL fields + Connect disabled. Banner includes detected-distro install command + Copy button (§9 table) and the sudoers nano tip.
- **In-window icons must be drawn as egui painter shapes** (`status_dot`, `arrow`, `warn_icon` in view/main_window.rs) — egui's default fonts (Ubuntu-Light, NotoEmoji) lack ↓/↑/●/⚠ and render them as empty squares. Tray-menu text is Plasma-rendered with system fonts and may use Unicode freely.
- Main screen shows field values read-only (dropdown switches profile); editing happens only in the ✎ modal. Profile switching is **disabled while a session is active** (no mid-session switch).
- Modal editor: name, server, username, trust checkbox + cert hash, optional interface override; Delete button (confirm dialog), Save/Cancel.
- Disable matrix: while Connecting/Connected → server/user/cert/trust and profile dropdown disabled; password editable only when Idle/Failed.

## 7. Window & tray behavior

- **Close (X)** → the window is destroyed for real (session loop + X11/XWayland backend): gone from screen and taskbar; the process keeps running headless (tray menu handled by the pump loop). Restore via tray `Open`/`Connect` or a second launch. Wayland sessions without XWayland: minimize fallback instead. **Minimize** → normal minimize. App exits only via tray Exit (confirm when connected: "Disconnect and exit?").
- System notifications (notify-rust, org.freedesktop.Notifications) fire on: connected (with interface name), manual disconnect, interface disappearance, VPN process exit, and connection failures (sudo rejection, openfortivpn exit). They are fire-and-forget (6 s timeout); failures are logged to stderr, never fatal. No notification on external-session adoption at startup.
- Tray icon (assets/icon PNG): green overlay when connected, gray idle, yellow while connecting, red missing-binary.
- Tray menu (dynamic):
  - `Open` — (re)open/focus window
  - `Connect` (when disconnected) / `Disconnect` (when connected)
  - `Status` (disabled info item, refreshed 1 Hz while connected): `↓ 12.4 MB ↑ 3.1 MB · 210 KB/s`
  - `Exit`
- External session adoption: on startup, `pgrep -x openfortivpn` found → state `Connected (external)`, stats from live `ppp*`; Disconnect sends SIGTERM to that pid.

## 8. Stats

- Source: `/sys/class/net/<iface>/statistics/{rx,tx}_bytes`, 1 Hz.
- Totals = bytes − baseline captured when interface appears; MB = bytes/1024²; speed = delta/s → KB/s. Shown split ↓/↑ in window and tray Status item.

## 10. Packaging (user-level only)

- `packaging/install-user.sh`: binary → `~/.local/bin/openfortivpn-gui`; PNGs → `~/.local/share/icons/hicolor/<size>x<size>/apps/openfortivpn-gui.png` (+SVG in `hicolor/scalable/apps/`); desktop → `~/.local/share/applications/openfortivpn-gui.desktop`; `update-desktop-database ~/.local/share/applications`, `gtk-update-icon-cache`. `--uninstall` flag reverses.

## 11. Docker workflows

- `docker/Dockerfile`: `archlinux:base-devel`, `pacman -S rust gtk3 libayatana-appindicator librsvg git`, non-root builder.
- `make dev-run`: container with `-e DISPLAY`, `-v /tmp/.X11-unix`, repo bind-mount, `cargo run` (host must allow X11: `xhost +si:localuser:$USER`). Live VPN connection testing happens on the host binary, not in the container.
- `make build`: multi-stage → binary copied to `./dist/`.
- `make icons`: rsvg-convert SVG → all PNG sizes.
- `make install-user`: build + run install script.

## 12. Security rules

- Never persist VPN or sudo passwords; temp config files 0600 and deleted on exit; never put secrets on argv; never log secrets; profiles.json written 0600.
- About dialog text includes: name, version (CARGO_PKG_VERSION), "Developed with AI assistance.", stack note.

## 13. Known limitations (v1)

- One VPN connection at a time; manual reconnect only (no auto-reconnect).
- OTP/2FA prompts cannot be answered from GUI (no TTY); documented in About/help if hit.
- GNOME requires the AppIndicator extension for the tray (Plasma/XFCE fine).
- Wayland sessions: the window runs on XWayland (forced X11 backend) so close-to-tray destroys and recreates windows; tray `Open` cannot restore a merely-minimized window on raw Wayland (winit exposes no un-minimize) — taskbar click needed. Without XWayland, close falls back to minimize.

## 14. Verification checklist (every PR touching behavior)

- `cargo fmt --check`, `cargo clippy -- -D warnings`, `cargo test` in container.
- Unit: profiles serde roundtrip; distro detect; command assembly asserts no secret in argv.
- Manual smoke: launch → window opens; rename openfortivpn in PATH → red banner + disabled UI; connect real profile → ppp appears, stats grow, tray Status updates; Close → window destroyed (KWin client count 0), process alive in headless tray loop (`[ofg] pump` lines on stderr); tray Open/Connect recreates the window; Disconnect kills ppp; Exit quits clean (no leftover pppd, temp config removed).
- Debug hooks: `OFG_SMOKE_CLOSE_MS=<ms>` simulates the X button after N ms (same code path as a real close) so close behavior can be tested programmatically; `[ofg +Nms]` stderr lines timestamp session transitions and a 2 s heartbeat proving the loop is alive while hidden/minimized.

## 15. Decisions (resolved 2026-09-29)

- Q1 UI stack: **egui + tray-icon** (cxx-qt rejected: build complexity for no functional gain here).
- Q2 sudo password when no NOPASSWD: **remember for session** (RAM, `Zeroizing`, cleared on exit/auth failure; never written to disk).
- Q3 cert UX: **manual hash field + auto-capture** from openfortivpn stderr with "Trust this certificate" offer.
- Q4 dev workflow: **Makefile + Dockerfile** (no devcontainer.json).
